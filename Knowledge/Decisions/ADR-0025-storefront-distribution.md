# ADR-0025 — Storefront Distribution and Canonical Public URL

Status: Accepted
Date: 2026-09-16

## Context

Phase 15A turns `/u/:username` into the generated public Hustle storefront. Phase 15B needs that storefront to distribute cleanly outside Hustle without creating a second website identity or copying Hustler data into another publishing system.

A shared storefront link must resolve to one canonical public URL, expose useful social/SEO metadata, and give a visitor deliberate sharing paths. The distribution layer must not expose private trust/safety or authenticated account data.

## Decision

1. The canonical storefront URL remains `/u/:username` on the configured Hustle web origin.
2. The public web origin is resolved from `NEXT_PUBLIC_WEB_URL`, then server `WEB_ORIGIN`, with `http://localhost:3001` as the local-development fallback.
3. Dynamic storefront metadata is generated from the public storefront aggregate only.
4. Metadata may include public identity, headline, professional summary, public imagery, published-offer counts and verified public reputation.
5. Private feedback, reports, blocks, moderation state and Admin intelligence are prohibited from metadata and share payloads.
6. The storefront publishes canonical, Open Graph and X/Twitter metadata for the same URL.
7. Share actions use the canonical storefront URL rather than the current browser URL, preventing query strings/fragments from becoming share identity.
8. Explicit distribution actions include copy link, native share, WhatsApp, X and QR.
9. Instagram does not have a general-purpose web share-intent URL; native platform share remains the supported path where the browser/device exposes it.
10. The MVP QR image may be generated by a public QR image service from the already-public canonical URL. This dependency can later be replaced with first-party QR generation without changing the canonical URL contract.

## Consequences

- A Hustler shares one durable identity URL everywhere.
- Search/social previews reflect authoritative public Hustle data.
- Query parameters and local navigation state do not become the storefront identity.
- Distribution remains a projection of the same Hustle identity rather than a second website-builder product.
- QR generation has an external image-service dependency in the MVP; the encoded value itself is public data.

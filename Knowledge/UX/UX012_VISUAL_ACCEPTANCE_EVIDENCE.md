# UX012 — Figma V1 Visual Acceptance: real screenshot evidence

**Status:** Implementation and automated public-shell capture. Full design-to-runtime visual parity **NOT VERIFIED**.

Design reference: https://www.figma.com/design/psxnn95X8nPqEEp7IvEw5s/Hustle-%E2%80%94-Mobile-Experience-V1?node-id=0-1

## Confirmed from source inspection

1. **Connected Explore chip regression (fixed):** UX011 accidentally displayed verbose accessibility strings visibly — "Top search results", "Search skill Beauty" — making chips inconsistent with Figma's compact Top/People/Posts/Services/Products and Beauty/Fashion/etc. UX012 separates the short visible labels from the complete screen-reader names without changing search endpoints or selection logic.
2. **Native keyboard-first close mismatch (fixed):** The offline demo already hides the keyboard before closing a sheet. The connected Experience had immediate close handlers. UX012 adds keyboard-first dismissal for social and opportunity sheets while retaining the existing confirmation when an enquiry may be in flight. This is a code-path correction; **requires Android/IME manual acceptance**.
3. **Missing screenshot evidence (addressed for public Web/PWA shells):** Earlier 320–1440px smoke tests checked overflow and route presence but uploaded only a JSON summary. UX012 now captures one screenshot per public shell per viewport, with safe loopback-only requests, into a **7-day review artifact**. No sign-in or external traffic is performed.

## GitHub Actions evidence

## Safety and repeatability

- No accounts/passwords/production data or Figma images are committed.
- The capture script refuses non-127.0.0.1 servers and blocks nonlocal browser requests.
- A screenshot is **not** a substitute for device tests, Figma frame comparison, interaction tests or accessibility audits.
- Check CI green before merging. No automatic production deployment.

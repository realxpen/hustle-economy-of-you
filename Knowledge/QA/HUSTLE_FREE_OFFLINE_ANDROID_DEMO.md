# Hustle Free Offline Android Demo — Cloud Build and Acceptance
Date: 2026-10-19
Status: **PR prepared. No EAS build has been launched and no APK exists yet.**

## User decision
- No Supabase subscription and **no separate staging environment**.
- No local workstation, Node installation, Expo CLI or terminal tasks for the owner.
- Deliver a completely free-to-build Android prototype first via the existing @xpen/hustle Expo Free project.
- Closed unmerged isolated-staging PR #134. Existing production auth/DB and finance are out of scope.

## Architecture
- Original signed-in `MobileExperience` and NestJS API integration are unchanged for normal builds.
- `EXPO_PUBLIC_HUSTLE_DEMO=true` opts into `apps/mobile/src/experience/DemoExperience.tsx` **before** any Supabase session initialization. It never calls a network API or accesses client databases.
- Four fictional sample Hustlers, with artistic poster-style **illustrations, not playable videos**. Likes, threaded comments, collections, follows, searches, creator preview, offer sheets and booking-slot UI use in-memory React state. State resets on app restart.
- No real businesses, verification, transactions, signing-in, availability, maps, media streaming, escrow, checkout or messages.
- Android build uses separate app ID `com.hustle.economyofyou.preview` owned by @xpen, with public EAS project UUID `b52b03ef-37f1-4bdf-ab42-5c80e5988ec4`.
- EAS `demo` profile is in the **development EAS environment**, not the `preview` environment that might later contain real staging credentials. Every `EXPO_PUBLIC_API_URL` / `EXPO_PUBLIC_SUPABASE_URL` profile value is a deliberately invalid `.invalid` host; booking writes hard-disabled.
- Workflow `.github/workflows/hustle-offline-android-demo.yml` is **manual-only**, requires GitHub environment `mobile-preview` with existing private EXPO_TOKEN and `approve_free_demo_build=true`. It invokes EAS Build `--profile demo --non-interactive --no-wait`, never submits to app stores. A build may consume **one** Expo Free monthly Android build allowance. If quota or first-time Android signing is blocked, stop and report; **do not** upgrade, purchase credits or enable payments.

## Cloud-only sequence for owner
1. Review and merge the demo PR **only after Mobile Cloud CI + Foundation CI pass**.
2. Open GitHub Actions: `Hustle Free Android Demo APK (manual)`.
3. Click **Run workflow**, select `main`, tick **I approve one Expo Free-tier Android DEMO build**, then click Run. This is the only action that attempts to consume a free build allowance.
4. Once GitHub finishes, the job summary links the Expo build dashboard: https://expo.dev/accounts/xpen/projects/hustle/builds . Check the exact Android `demo` build for completion and the **APK** artifact.
5. Download/install APK on an Android phone with the user's own consent to sideload. The signed installable package is generated by Expo; a passing GitHub workflow may only mean **queued**, not built. Do not claim success until an EAS artifact exists.

## First Expo build incident — 2026-10-19 (corrected on review branch)
- EAS Android demo build `4253c101-ad17-4f55-9526-37bad8e24911` **failed** at `Bundle JavaScript`; there is no downloadable APK from that build. Expo UI says the failed build **does not count toward EAS Build usage**.
- Root cause reproduced in free GitHub CI: `ConfigError: Cannot resolve entry file: The main field defined in your package.json points to an unresolvable or non-existent path.`
- Previous `apps/mobile/package.json` used `node_modules/expo/AppEntry.js`, a path unavailable inside the hoisted npm workspace layout. Remediation sets `main: index.js` and registers `App` via Expo's `registerRootComponent` in `apps/mobile/index.js`.
- Free GitHub Actions Android Metro export **passed** after this change, bundling 726 modules. Include that export in both Mobile Cloud CI and the manual EAS queue workflow **before** issuing any EAS build request.
- A green Metro export validates the JavaScript bundle, not Android native Gradle packaging, APK install or touch interactions. Owner approval is still required for a retry via the manual EAS workflow; no paid service or extra staging database is needed.
